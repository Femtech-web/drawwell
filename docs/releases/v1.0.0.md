# Drawwell v1.0.0

**Prepare a Department of Education G5 drawdown you can defend, line by line.**

Since November 1, 2026, every Department of Education grant recipient must justify each G5 payment request in 255 characters or fewer: the program, the expense categories and amounts, and the expense dates. Drawwell checks the draw before the justification is written. Code proves the errors, SERV Reasoning applies 2 CFR 200 to every expense and receipt, and the grant administrator makes the judgment calls.

**Live:** https://drawwell.vercel.app · **Demo video:** https://youtu.be/keEElunJfV0 · **For judges:** [JUDGES.md](../../JUDGES.md)

Built for the OpenServ SERV Hackathon Edition 02, Open Track.

## What's in this release

**Review a drawdown**
- Pick a sample award, or upload your approved budget (ED Form 524 categories) and a ledger export as CSV. Malformed files get line-numbered errors before anything is sent.
- Receipts as **PDF** (read as text on the server) or text files, plus optional award terms.
- **Code checks** against your own records: invoices already drawn, the same invoice twice, costs outside the budget period, unpaid costs on a reimbursement award, advances drawn before the cash is needed, categories over the approved budget, items above the equipment threshold, and text addressed to an AI.
- **SERV Reasoning** reads each remaining expense with its receipt, the award terms and 25 sections of 2 CFR 200 (eCFR snapshot). It decides the budget category, whether the cost is allowable or needs judgment, what the receipt actually totals, and which line inside a larger charge is unallowable.
- **Verification in code:** a citation is kept only if its quote appears word for word in the cited rule or award term. A receipt total counts only if the quoted line is in the document. The model can never create a blocking error on its own.
- **Your decisions:** exclude a row, remove the unallowable part of a charge, or keep it after checking. Costs that depend on exceptions or the award are never rejected automatically.

**Write and keep the justification**
- SERV drafts the 255-character G5 justification from the final, code-computed totals. Code checks every required element: program name, every category with its exact amount, amounts that add up, expense dates, no personal information. The checks rerun as you edit.
- An evidence report traces every dollar to its row, document, rule and decision, and lists each SERV call with its model, features and request ID. Print it, save it as PDF, or download the JSON.

**For state education agencies**
- A reviewer view checks a whole queue of district justifications against ED's required elements and shows the exact gap for each. It runs entirely in the browser.

## How SERV Reasoning is used

Every review is a live call to SERV with **Multipath** (the cost principles are a branching policy matrix), **Shadow Agent** (the draft is validated against a testable hint before SERV answers), **Prompt Guard** (receipts are third-party text) and a **strict JSON schema** whose enums come from the request. SERV sometimes answers empty or slowly, so each review gives full features 150 seconds, then retries without Prompt Guard, then with the features off. Every attempt is recorded with the features it used.

## Proof

A frozen benchmark: four synthetic drawdown requests, 37 labeled expenses, one request held out of prompt development, graded in code.

| | Code rules only | One plain SERV call | Drawwell, features off | **Drawwell** |
|---|---|---|---|---|
| Defensible allowability | 30/37 | 31/37 | 36/37 | **37/37** |
| Unsafe misses | 4 | 0 | 0 | **0** |
| Held-out request | 10/12 | 11/12 | 11/12 | **12/12** |
| False receipt mismatches | 5 | 4 | 0 | **0** |
| Unallowable lines isolated to the cent | 0/3 | 0/3 | 2/3 | **3/3** |
| False partial removals | 0 | 12 | 0 | 1 |
| Citations kept word for word | n/a | unchecked | 67/72 | **47/48** |
| Time for 4 requests | 0 s | 51 s | 36 s | 445 s |

Every run, failures included, is in [`docs/results/`](../results/) and on the [Evaluation page](https://drawwell.vercel.app/evaluation).

- 43 unit tests: CSV parsing, money, every code check on every sample, justification checks, SERV-output verification with fabricated responses, the empty-response fallback, PDF extraction and the reviewer checks.
- End-to-end runs on the production build and the deployed site with live SERV calls, including a review whose receipts were all PDFs.

## Known limits

- Department of Education G5 only; other agencies' systems are not covered.
- 25 sections of 2 CFR 200; program statutes and EDGAR program rules only if supplied as award terms.
- Scanned or photographed receipts are not read (PDFs need a text layer).
- Sample awards and the benchmark use fictional organizations and synthetic records; 37 labeled rows, written by the builder.
- With all SERV features on, a review takes about a minute and occasionally longer.
- Drawwell prepares a request. It does not submit to G5 or approve payments, and passing its checks is not approval.
